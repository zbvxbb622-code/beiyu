# 杯语代码层面可解决问题清单

更新时间：2026-08-02

本文只整理当前可以通过修改前端、后端、配置或文档直接推进的问题。需要第三方服务、公司主体、备案材料才能完成的事项，会标注为“可先做代码骨架”。

## 1. 结论

当前代码已经可以支撑本地 Demo，但仍有一批问题可以继续通过代码修复，提高 Demo 稳定性并为上线铺路。

推荐优先顺序：

1. 账号注销数据清理。
2. 社区举报、审核和内容状态。
3. 隐藏或改造假功能。
4. 图片上传接口骨架。
5. 实名认证后端化。
6. AI 合规展示和分享标识。
7. 生产配置校验、构建配置和文档。

## 2. P0：建议优先修复

### 2.1 账号注销数据清理

当前问题：

- 后端已有 `/me/account` 注销接口。
- 当前主要清理用户资料、设备、会话、酒柜。
- AI 会话、AI 消息、AI 记忆、社区帖子、评论、点赞等缺统一删除或匿名化策略。

代码修复方向：

- 后端新增账号注销清理服务。
- 注销时处理：
  - AI conversations。
  - AI messages。
  - AI memories。
  - AI memory sources。
  - community posts。
  - community comments。
  - community likes。
- 明确策略：删除、匿名化或依法保留。
- 增加后端测试，覆盖注销后数据不可再关联到原手机号和原用户身份。

验收标准：

- 注销后无法再用旧 refresh token。
- 注销后个人资料脱敏。
- 注销后社区内容按策略删除或匿名化。
- 注销后 AI 历史不可再被用户读取。

### 2.2 社区举报与审核基础能力

当前问题：

- 已有社区帖子、评论、回复、点赞。
- 已补举报表、审核状态、审核审计日志、用户举报 API、管理员审核 API。
- 仍缺运营可视化审核后台、细分审核角色和举报频率限制。

后续代码修复方向：

- 新增运营审核后台 UI。
- 新增 `MODERATOR` 或 `COMMUNITY_ADMIN` 权限。
- 增加举报时间窗口频率限制。
- 前端举报表单支持原因、详情和二次确认。

验收标准：

- 用户可以举报帖子和评论。
- 被隐藏或拒绝的内容不在普通社区流展示。
- 管理员处理动作有审计记录。
- 运营人员可以在后台处理举报。

### 2.3 社区内容状态控制

当前问题：

- 帖子和评论已有 `approved`、`hidden`、`rejected` 状态。
- 当前发布仍默认通过，适合 Demo；生产需要接入机器审核或人工审核队列。

后续代码修复方向：

- 发帖默认 `pending` 或 `approved`，按环境配置决定。
- 列表接口默认只返回 `approved` 内容。
- 作者本人可以看到自己的 `pending/rejected` 内容和原因。
- 评论同样增加状态控制。

验收标准：

- 普通用户看不到未审核或已隐藏内容。
- 作者能看到自己的审核状态。
- 管理员能改变审核状态。

### 2.4 隐藏或改造假功能

当前问题：

以下功能有 UI，但当前不是真实生产能力：

- 官方认证。
- 微信绑定。
- 登录密码修改。
- 私人酒柜上传封面。
- 酒吧附近推荐。
- 部分设置页二级页面。

代码修复方向：

- 短期方案：隐藏入口或改为“暂未开放”。
- 中期方案：接真实后端状态和接口。
- Demo 版本避免让老板误认为已经完成生产能力。

验收标准：

- 用户无法点击进入假流程。
- 已保留入口的页面必须明确展示“暂未开放”。
- 测试覆盖关键入口是否隐藏或禁用。
- 本轮已处理一批假入口；仍需继续处理 AI 标题下拉、盲盒测试抽卡入口等 Demo 体验问题。

## 3. P1：可以同步推进

### 3.1 图片上传接口骨架

当前问题：

- 相册图片只是本地 URI。
- 后端只是保存图片 JSON。
- 没有对象存储、CDN、审核状态。

代码可先完成：

- 后端新增媒体表：
  - media id。
  - owner id。
  - bucket。
  - object key。
  - url。
  - status。
  - created at。
- 新增上传凭证接口：
  - `POST /api/v1/media/upload-credentials`
- 新增媒体确认接口：
  - `POST /api/v1/media/{mediaId}/complete`
- 帖子图片从 `file://` 改为 media id 或 CDN URL。
- 前端发布页改为先上传图片，再提交帖子。

仍需外部服务：

- OSS/S3/R2。
- CDN。
- 图片审核服务。

验收标准：

- 前端不再把 `file://` 当作社区公开图片提交。
- 换设备后帖子图片仍可访问。
- 图片有审核状态字段。

### 3.2 实名认证后端化

当前问题：

- 身份证年龄校验主要在前端。
- 后端只有年龄确认状态，没有真实实名核验链路。

代码可先完成：

- 新增后端实名接口：
  - `POST /api/v1/me/realname-verification`
- 前端只提交姓名和身份证号到后端。
- 后端执行格式校验、年龄校验、频控。
- 预留第三方实名 Provider 接口。
- 后端只返回通过、未成年、格式错误、服务不可用等状态。
- 不保存身份证明文。

仍需外部服务：

- 二要素或三要素实名服务商。

验收标准：

- 前端不直接决定实名通过。
- 未满 18 岁不能继续注册或登录。
- 日志、本地存储、AI 上下文不出现身份证明文。

### 3.3 AI 合规展示和分享标识

当前问题：

- AI 聊天页已有基础提示。
- 设置页或关于页缺模型服务商、模型名称、备案号或上线编号。
- AI 内容分享到社区时没有统一 AI 生成标识。

代码修复方向：

- 设置页新增“AI 服务说明”页面。
- 展示：
  - 服务商。
  - 模型名称。
  - 内容由 AI 生成提示。
  - 备案号或上线编号占位。
- AI 生成内容分享到社区时，帖子带 `aiGenerated=true`。
- 社区卡片和详情页展示 AI 生成标识。

验收标准：

- AI 聊天页有清晰提示。
- AI 分享内容有标识。
- 设置页可查看模型和合规信息。

### 3.4 生产配置校验

当前问题：

- 后端已限制非 dev 环境不能用 development AI/SMS provider。
- 但前端和部署环境仍需要更完整的 staging/prod 校验。

代码修复方向：

- 增强后端配置校验：
  - prod 必须使用强 secret。
  - prod 必须配置真实数据库 URL。
  - prod 必须禁用固定验证码。
  - prod 必须配置 AI provider 或明确关闭 AI。
- 前端构建时校验：
  - prod 必须配置 HTTPS API URL。
  - prod 不允许 `127.0.0.1` 或局域网地址。
- 新增配置测试。

验收标准：

- 错误配置无法启动生产环境。
- 生产包不会指向本机 API。

### 3.5 错误提示统一

当前问题：

- 部分失败提示仍可能显示 `request-failed`、`invalid-response`。
- Demo 时不利于定位问题。

代码修复方向：

- 建立统一错误码到中文提示的映射。
- 覆盖：
  - 登录。
  - 短信。
  - AI。
  - 社区发帖。
  - 评论。
  - 图片上传。
  - 内容刷新。
- 前端 Alert 和页面错误状态统一使用可读文案。

验收标准：

- 用户看不到裸错误码。
- 开发日志仍保留错误码，方便排查。
