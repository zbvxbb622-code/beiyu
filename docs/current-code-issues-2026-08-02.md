# 杯语当前代码问题清单

更新时间：2026-08-02

本文基于当前分支 `codex/stage3-ai-acceptance` 的代码核查结果整理，用于区分当前已经可演示的能力、仍需开发的问题、外部服务或备案问题，以及看起来有 UI 但尚未真正完成的功能。

## 1. 总结结论

当前版本已经达到本地 Demo 和老板演示的 MVP 状态：

- 前端主要页面可用：登录、首页、AI 聊天、社区、发帖、评论、酒谱、酒吧、经典盲盒、我的、设置、实名认证、隐私协议。
- 后端已有账号、内容、酒柜、AI 会话、AI 记忆、额度、临时聊天、社区帖子、评论、点赞等基础接口。
- AI 聊天已经接入后端 Provider 边界，开发环境可用本地 provider，配置后可走阿里云百炼兼容接口。
- 当前自动化测试通过，代码基础状态较稳。

但是，当前版本还不能直接公开上线。主要原因不是单纯备案，而是仍缺生产级实名、短信、图片上传、社区审核、举报、监控、云部署和 App 发布配置。

## 3. P0 上线前必须修复

### 3.1 实名认证不是真实实名

当前状态：

- 前端 `src/app/realname-verify.tsx` 收集姓名和身份证号。
- `src/utils/identityVerification.ts` 只校验身份证格式、校验位、生日和是否满 18 岁。
- 后端 `FeatureFlags.legal_name_verification` 默认为 `false`。
- `src/state/MixologyState.tsx` 中 `verifyRealname` 只是把本地账号安全状态标记为已实名。

风险：

- 不能证明用户身份证号与姓名真实匹配。
- 不能满足酒类、社交、内容发布场景下的实名与年龄核验要求。

需要补齐：

- 后端接第三方二要素或三要素实名服务。
- 前端实名信息只提交后端，不直接调用实名服务商。
- 后端只保存实名通过状态、认证时间、供应商流水号、脱敏审计信息。
- 不保存身份证明文，不写入本机 AsyncStorage/SecureStore，不进入 AI 上下文。
- 增加实名失败、未成年、频控、服务商不可用等错误状态。

### 3.2 图片上传不是真实云上传

当前状态：

- `src/services/postImagePickerService.ts` 只从相册获取本地 `file://` URI。
- `src/state/MixologyState.tsx` 发帖时直接把本地 URI 放进 `images`。
- 后端 `backend/app/modules/community/service.py` 只是把图片 JSON 存入数据库。
- 后端没有 OSS/S3 上传凭证接口，没有对象存储表，没有 CDN URL，没有图片审核状态。

风险：

- 换设备或重装后图片无法访问。
- 服务器、其他用户、审核后台无法稳定读取本地图片。
- 图片不能做违规审核，社交公开内容风险很高。

需要补齐：

- 新增媒体模块：上传凭证、对象存储 key、CDN URL、媒体状态。
- 接入 OSS/S3/R2 等对象存储。
- 图片上传后先进入待审核状态。
- 审核通过后公开展示，失败则隐藏并提示用户。

### 3.3 社区缺举报和审核闭环

当前状态：

- 已有社区帖子、评论、回复、帖子点赞、评论点赞接口。
- 数据模型没有举报表、审核工单、审核状态、封禁处理、内容下架记录。
- 评论和帖子发布后缺生产级内容审核。

风险：

- 违规内容可能直接公开。
- 用户无法举报帖子、评论或用户。
- 管理员无法追踪审核处理过程。
- 上线社交功能时合规风险高。

需要补齐：

- 新增举报接口：举报帖子、评论、用户。
- 新增审核状态：`pending`、`approved`、`rejected`、`hidden`。
- 新增审核后台：工单列表、处理动作、下架、恢复、封禁。
- 文本敏感词和模型审核。
- 图片审核。
- 审核日志和操作审计。

### 3.4 账号注销清理不完整

当前状态：

- `/me/account` 删除账号接口存在。
- 后端目前主要处理用户状态、资料、设备、会话、酒柜。
- AI 会话/消息、AI 记忆、社区帖子/评论、点赞等没有统一删除或匿名化策略。

风险：

- 用户注销后，历史内容和 AI 数据可能残留。
- 隐私合规和用户数据删除要求不完整。

需要补齐：

- 明确注销策略：删除、匿名化或按法规留存。
- 覆盖 AI 会话、AI 消息、AI 记忆、社区帖子、评论、点赞、举报记录。
- 补充数据删除测试。
- 前端注销确认页展示清楚哪些数据会删除、哪些依法留存。

### 3.5 生产短信登录未接入

当前状态：

- 开发环境使用固定验证码 `123456`。
- 后端配置已禁止非 dev 环境使用 development SMS Provider。
- 但生产短信 Provider 尚未实现。

风险：

- 生产环境不能使用固定验证码。
- 老板 Demo 可以本地跑，但真实上线必须接短信服务。

需要补齐：

- 接入阿里云短信、腾讯云短信或其他短信服务。
- 配置签名、模板、频控、防刷。
- 短信发送失败有明确错误提示。
- 记录发送成功率、失败率、供应商错误码。

## 6. 安全与敏感信息问题

### 6.1 本地真实 AI Key 需要轮换

当前状态：

- `backend/.env` 被 `.gitignore` 忽略，没有提交。
- 但 `docker compose config` 会展开本机真实环境变量。

风险：

- 如果把 compose 输出、终端截图、日志发给别人，可能泄露真实 Key。

建议：

- 立即避免公开本地 compose 输出。
- 对已经展示或截图过的 AI Key 做轮换。
- 后续所有日志、验收报告中对 `BEIYU_AI_API_KEY` 脱敏。

### 6.2 依赖漏洞

当前状态：

- `npm audit --omit=dev --audit-level=high` 未发现 high/critical。
- 发现 11 个 moderate，来自 Expo 依赖链中的 `uuid`。
- `npm audit fix --force` 会导致 Expo 依赖破坏，不建议直接执行。
- `uvx pip-audit` 未发现 Python 已知漏洞。

建议：

- 暂不强制修 Expo 依赖链。
- 等 Expo 官方升级或做受控升级测试。
- 上线前重新执行 npm audit、pip-audit。

## 8. 备案和合规缺口

以下不是法律意见，最终需由公司主体、云服务商、律师或合规顾问确认。

### 8.1 ICP / App 备案

需要准备：

- 公司主体信息。
- 域名。
- 云服务器信息。
- App 名称、图标、包名、版本。
- 服务内容说明。

### 8.2 公安联网备案

需要准备：

- 域名。
- 服务器 IP。
- 主体资料。

- 身份信息最小化策略。

### 8.5 AI 软件相关要求

- 模型服务商信息展示。

## 9. 推荐修复顺序

第一阶段：稳定老板 Demo

1. 固定 demo 账号、demo 数据、demo 启动脚本。
2. 修复明显 UI 问题和演示路径问题。
3. 明确哪些功能是演示能力，避免老板误解为已上线能力。

第二阶段：补生产核心闭环

1. 图片上传和对象存储。
2. 社区举报、审核、下架、封禁。
3. 真实实名认证。
4. 生产短信服务。
5. 账号注销数据清理。

第三阶段：准备上线

1. 云数据库、服务器、域名、HTTPS。
2. 生产环境变量和密钥管理。
3. 监控告警和备份恢复。
4. EAS/TestFlight/Android 内测。
5. 正式隐私政策、用户协议、社区规范。

第四阶段：备案和正式发布

1. ICP/App 备案。
2. 公安联网备案。
3. 社交评论审核制度落地。
4. AI 备案或登记路径确认。
5. 小范围灰度上线。

## 10. 当前结论

当前代码可以用于本地演示和内部 Demo，但不建议直接公开上线。真正上线前，必须至少完成真实实名、生产短信、图片云上传、社区审核举报、账号注销清理、生产部署和合规材料。
